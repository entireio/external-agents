  ## Adversarial review: `agents/entire-agent-sarvam` (diff vs origin/main)
  
  I found two medium bugs in `config.go`, both demonstrated. The rest are low severity. I demonstrated each config finding with a throwaway in-package test, `internal/sarvam/zz_scratch_test.go`. It ran a fresh install, then `AreHooksInstalled`, then a second install, then uninstall, and I checked each output with Python's `tomllib`. That test and its output directory are deleted, and `git status` is clean.
  
  ### Findings
  
  **1. A triple quote in a comment or ordinary string hides every hook below it — MEDIUM, demonstrated.** `config.go:154-158`
  - **Cause:** the check that opens a multi-line string counts `"""`/`'''` on the raw line. It ignores comments and ordinary quoted strings. After a false match, every following line is treated as body until another delimiter appears, so no `[[hooks...]]` header below is recognized.
  - **Input:** a config containing `# Tip: wrap long prompts in """ like this` or `notify = "echo '''"`.
  - **Result:**
    - First install adds 4 entries, but `AreHooksInstalled` returns `false`.
    - A second install adds 4 more, giving 8 entries.
    - Uninstall removes none, so all 8 remain.
  - **Impact:** every `entire enable` duplicates the hooks. If they are trusted they fire twice, giving duplicate turn-start and turn-end events, and uninstall cannot clean up. The neighbouring `netBracketsOutsideQuotes` already handles quotes and `#` correctly; this check needs the same treatment.
  
  **2. Install breaks a config that defines hooks inline or with dotted keys — MEDIUM, demonstrated.** `config.go:363-383`, `:458`
  - **Cause:** `checkNoMapFormEvents` only rejects the `[hooks.<Event>]` header form. It misses `[hooks]` followed by `Stop = [{ hooks = [...] }]`, and a top-level `hooks.Stop = [...]`. `headerEvent("[hooks]")` doesn't match the `[hooks.` prefix, so install appends `[[hooks.Stop]]` after the inline definition.
  - **Result:** `tomllib` rejects the output: `Cannot mutate immutable namespace ('hooks','Stop')`. Sarvam would reject the whole config, so all hooks, including the user's own, stop working. The command still reports success (`install=4`, no error).
  
  **3. Spaced or quoted header forms are not recognized — LOW, demonstrated.** `config.go:65`
  - **Input:** a pre-existing Entire entry written as `[[ hooks.Stop ]]` / `[[ hooks.Stop.hooks ]]`, which is valid TOML, or with a quoted key like `[[hooks."Stop".hooks]]`.
  - **Result:** install adds a second Stop entry (5 total), and uninstall leaves the original behind (1 remaining).
  
  **4. CRLF files end up with mixed line endings — LOW, demonstrated.** `config.go:317-321`, `:440`
  - New blocks and in-place command rewrites are written with `\n` only, so a CRLF file gets mixed endings. The TOML still parses; this is cosmetic.
  
  **5. Shell-command path extraction gives false positives and misses some writes — LOW, demonstrated.** `transcript.go:205-208`
  - **Input:** `echo "a > b" && git commit -m "fix: x > y" && make &> build.log && cp a.txt b.txt && rm old.txt`
  - **Result:** reports `["b","y"]`. `build.log`, `b.txt`, and the deletion of `old.txt` are missed. Targets outside the repo, such as `> /tmp/x`, are also returned unfiltered.
  
  **6. AGENT.md doesn't match the install behaviour — LOW, reasoned.** `AGENT.md:173`
  - It says install writes `matcher = ".*"` for tool events, but no tool events are installed (`types.go:45-50`, README:21).
  
  **7. E2E adapter runs an extra paid LLM call per prompt — LOW, reasoned.** `e2e/agents/sarvam.go:209-228`
  - `RunPrompt` calls `StartSession`, and `trustRepo` runs a real `sarvam-code exec` call every time, so each prompt test makes two model calls. That adds cost, time, and a second chance of a transient failure.
  - The hook-state key `...:<event>:0:0` (line 283) assumes Entire's hooks are the first matcher group and first entry for each event. That holds in a fresh test repo but nowhere else.
  - Otherwise the adapter is sound:
    - **Environment:** each session gets its own tmux socket and server, so `SARVAM_HOME` reaches the TUI and the hook subprocesses.
    - **Real-home guard:** it refuses to run against the real `~/.sarvam`.
    - **Stale trust hashes:** it fails loudly when the trust hashes are out of date.
  
  **8. Committed fixtures contain a personal path — LOW.** `testdata/hook-payloads/*.json`
  - They include `/Users/soph/...`. This is harmless, but it is a personal path in committed fixtures.
  
  ### Checked and OK (including previously raised items now fixed)
  - **Config parsing and editing:**
    - multi-line arrays, including a `[` inside a trailing comment
    - `[[hooks.X]] # comment` headers
    - `type = "command" # c` lines
    - no trailing newline
    - file permission preserved
    - repair of entries missing their `[[hooks.<Event>]]` group, persisted even when 0 entries were added
    - single-bracket table form rejected
    - `--force` with no leftover empty groups
    - a user's matcher group kept on uninstall
    - legacy pre-compact entries removed
    - untouched bytes when there is nothing to change
    - idempotency on clean configs, including CRLF
  - **Transcript reading:** a 200KB line is read correctly with no 64KB cap. A partial final line is excluded from the position and the modified-files list (position 2, files `[x.txt]`). Compaction keeps that final line when it parses.
  - **Tokens:** re-emitted cumulative `token_count` snapshots are not double-counted. The offset is a physical line index, consistent with `get-transcript-position`. The cached share is split out of input tokens.
  - **Hook parsing:**
    - accepts both native and protocol payloads
    - PreCompact maps to null and PostCompact maps to compaction
    - an empty prompt maps to null
    - the session ref falls back to the resolved rollout file
  - **Protocol and main:** they match qwen's dispatch and exit conventions, and a negative offset is rejected.
  - **Session writes:** `write-session` refuses to overwrite an existing native rollout, and restores to a rollout-named path that `sarvam-code resume` can find.
